# 2026-07-05

## AI 에이전트 하네스(Harness) 설계 방식 소감

* 배경: 프롬프트 엔지니어링 중심 접근의 한계를 느끼고 하네스 기반 설계 방식을 접함

* 하네스란

    * 프롬프트나 블랙박스 모델에만 의존하지 않고 모델 주변을 감싸는 결정론적이고 안정적인 실행 환경
    * 도구 레지스트리, 가드레일, 검증 단계 등으로 구성

* 주요 인사이트

    * **프롬프트 엔지니어링의 한계 극복**: 에이전트 오작동/환각 발생 시 프롬프트를 강화하는 대신, 가드레일과 하네스 수준의 자동 검증·인터셉트 로직으로 신뢰성을 높이는 접근
    * **라이브 디프로 보여주는 개선 방식**: 프롬프트를 유지한 채로 실제 결과를 개선하는 방법을 직접 보여주는 방식이 흥미로움
    * **검증 후킹**: 거짓말 방지를 위해 검증 훅을 걸고, 하네스 레벨에서 로그인 페이지 체크 등 환경 검증 수행
    * **LLM 격리**: 민감 정보를 LLM에게 넘기지 않고 프롬프트 변경 없이 미션을 성공하는 구조가 인상적

* 소감

    * 스포티파이의 프롬프트 컨텍스트 엔지니어링 방식을 선호해왔으나, 구현 범위가 커질수록 아웃풋 시간과 퀄리티가 저하되는 문제를 반복적으로 겪음
    * 컨텍스트 압축 관리, 가드레일, 에이전트 루프 도입을 고려해볼 시점이라는 생각
    * 프롬프트 엔지니어링 + MCP를 통한 검증 모델로 두 이점을 취할 수 있음

* 보완이 필요한 부분

    * 컨텍스트 압축 강조는 설득력 있으나, 압축에 따른 예측 가능성 저하는 추가 보완이 필요
